# 关键技术与产品决策

本文件记录已经确认、会影响后续实现或开源协作的决策。新决策应说明背景、选择和后果。

## D-001：新桌面端与原稳定工具隔离

- **背景**：原下载工具可用，优化试验不应破坏其工作流。
- **选择**：新代码独立位于 `smartedu-library-desktop`，不修改原工具。
- **后果**：新项目可独立测试、开源和发布；稳定工具保留为可用回退方案。

## D-002：采用 Electron 作为首个桌面壳

- **背景**：应用需要本地文件写入、受限登录窗口、私有会话和 Windows 首发体验。
- **选择**：使用 Electron + React，renderer 与 Node.js 通过受限 preload IPC 通信。
- **后果**：开发与发布依赖 Node.js/npm；后续需要提供安装包并控制 Electron 安全更新。Tauri 不作为当前首发实现，但不排除未来评估。

## D-003：登录留在应用内，且只保存在私有 session

- **选择**：使用 Electron `persist:smartedu-session`；登录窗口仅允许相关平台域名，登录成功自动关闭，用户可清除本应用 session。
- **后果**：用户不需要在外部浏览器登录；本地 session 数据属于敏感文件，必须被 Git 忽略且不得通过 IPC 暴露。

## D-004：分类聚合，资源独立

- **选择**：以学段、学科、年级、册次和版本分类聚合；`contentId` 仍是资源唯一身份，标题不参与身份和去重判断。
- **后果**：同名、同版、不同年度或内容的资源可同时展示和下载；单资源保持紧凑，多资源采用直接可见的父子行。

## D-005：下载默认安全完成，不默认省事跳过

- **选择**：文件名使用分类、资源年度和短 ID；`.part` -> 校验 PDF 头与大小 -> 原子改名。已下载状态只用于提示和批量选择。
- **后果**：不产生标题同名的 `(2)`、`(3)` 默认命名，也不阻止用户主动重新下载。

## D-006：目录变化提示延后设计

- **背景**：目录缓存可用于发现新增与更新，但“何时清除标记”尚未得到满意交互方案。
- **选择**：先不实现自动清除的变化提示；未来基于持久化快照和用户确认机制设计。
- **后果**：当前刷新目录不会宣称提供可靠的新增/更新提醒。
